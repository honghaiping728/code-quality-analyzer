# 前端端到端测试

用 Playwright 驱动**真实浏览器**跑控制台，覆盖后端单元测试触达不到的地方。

## 为什么需要它

控制台是 Vue 单页应用，页面行为没有单元测试能覆盖。结果是「扫描完成后问题列表
没有聚焦到本次任务」这类缺陷**不会让任何测试失败** —— 接口全部返回 200，
后端行为完全正确，只是页面上看不出刷新。

这套用例真实驱动一遍「粘贴代码 → 等待完成 → 跳转列表」，并断言列表**只展示本次任务的结果**；
同时覆盖分页、过滤、详情、主题切换与深链直达。

## 前置条件

1. **一个已启动的 cq-web**（默认 `http://127.0.0.1:8080`）。没起的话 Playwright
   会自己用 `java -jar cq-web/target/cq-web-0.1.0-SNAPSHOT.jar` 拉起来
   （`reuseExistingServer` 已开，本地通常自己起着更好）。
2. **Chromium**：`npm run install-browser`（等价于 `playwright install --with-deps chromium`，
   会一并安装 libgbm 等系统库）。
3. **中文字体**：`apt-get install -y fonts-noto-cjk`。缺了它截图里全是豆腐块，
   `--with-deps` 不负责装字体。

## 运行

```bash
cd frontend-test
npm install
npm run install-browser   # 首次
npm test
# 或指定地址
BASE_URL=http://192.168.20.131:8080 npm test
```

退出码 0 表示全部通过；失败时会在 `playwright-report/` 生成可交互报告
（`npm run report` 打开），并保留失败截图与 trace。

**写选择器一律用 `data-test` 属性**（`page.getByTestId('...')`）：模板里已经埋好，
比结构选择器稳定得多。注意 Element Plus 的属性透传位置不统一——
`el-input` 的 `data-test` 落在**内层 `<input>`** 上，`el-select` / `el-switch` 落在根元素上，
下拉与弹窗是 **teleport 到 body** 的，必须从 `page` 上找而不是从容器里找。

## 视觉核对

```bash
npm run shots        # 截图到 shots/，亮/暗两套 × 每个视图
```

`shots/` 是给人眼看的，不做像素比对：字体与渲染在不同机器上必然有差异，
拿它当断言只会得到一堆无意义的红。改动视觉后跑一遍、逐张看过即可。

## 覆盖范围

- 页面骨架：五个页签、概览默认激活、状态栏与主题按钮
- 概览：四种来源齐全、面板切换、上传表单的 `.java` 限制与多选、仓库增量模式的提交范围显隐、最近任务表
- **扫描全流程回归**：粘贴代码 → 轮询 → 自动跳转 → 列表聚焦本次任务（且不混入其他任务）
- 问题列表：分页（默认 20 条、翻页内容变化）、关键词过滤与 URL 同步
- 问题详情：从列表进入、返回
- 报告与趋势：趋势图、四维度图例、明细表
- 规则配置：规则表 / 阈值表 / 忽略列表三块都能落到终态（不会停在"加载中"）、规则可停用再启用
- 大模型配置：新增 → 密钥掩码显示（原文不出现）→ 启用状态与接口一致 → 删除清理
- 主题与路由：暗色切换与持久化、`--el-color-primary` 阶梯确实换掉、深链直达不 404
