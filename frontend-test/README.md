# 前端集成测试

用 jsdom 加载真实页面并驱动交互，覆盖后端单元测试触达不到的地方。

## 为什么需要它

控制台是原生 HTML/CSS/JS，没有构建步骤，也就没有单元测试能覆盖它。结果是
「扫描完成后问题列表没有聚焦到本次任务」这类缺陷**不会让任何测试失败** ——
接口全部返回 200，后端行为完全正确，只是页面上看不出刷新。

这个测试用真实 DOM 驱动一遍「粘贴代码 → 等待完成 → 跳转列表」，
并断言列表**只展示本次任务的结果**。

## 运行

需要先启动服务，然后：

```bash
cd frontend-test
npm install
npm test
# 或指定地址
BASE=http://192.168.20.131:8080 npm test
```

退出码 0 表示全部通过，非 0 表示有断言失败并会列出失败项。

## 注意

页面静态资源是**打包进 jar** 的。改了 `static/` 下的文件后必须重新构建并重启服务，
测试跑的才是新代码 —— 否则会出现「源码已改、测试仍失败」的假象。

```bash
mvn -q clean install -DskipTests
java -jar cq-web/target/cq-web-0.1.0-SNAPSHOT.jar
```

## 覆盖范围

- 页面结构：三个来源页签、默认视图
- 初始加载：状态栏、任务下拉
- 粘贴代码全流程：提交 → 轮询 → 自动跳转 → 列表聚焦到本次任务
- 任务筛选：「全部」视图能同时看到历史与最新结果
- 上传表单：`.java` 限制、多选、按钮存在
- 来源切换：面板切换正确

## 未覆盖

- 真实文件上传（jsdom 的 `FormData` 与 `File` 支持有限，上传走的是同一套 `pollTask`，
  核心跳转逻辑已被粘贴流程覆盖）
- 样式渲染（jsdom 不做布局，黑白风格需人工确认）
